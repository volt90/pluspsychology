> 특히 1장·7장은 판매 개시 전에 **세무사와 PG사에 직접 확인**해야 합니다.

## 1. 🚨 정산 계좌 — 주식계좌로는 받을 수 없습니다

> "해외결제를 달러로 주식계좌에 받는다"는 구조는 그대로는 실행할 수 없습니다.
> 아래 세 가지가 각각 걸립니다.

### ① PG사가 증권계좌를 정산계좌로 받지 않습니다
국내 PG사는 계약 시 **사업자등록증 + 사업자 명의 은행 계좌**를 요구합니다.
증권사 계좌(CMA 포함)는 정산계좌로 등록되지 않는 것이 일반적입니다.
해외 PG(Stripe 등)도 payout 대상은 은행 계좌입니다.

### ② 사업용계좌는 은행 계좌여야 합니다
소득세법 제160조의5에 따라 복식부기의무자는 **사업용계좌를 신고하고 사용**해야 하며,
사업용계좌는 은행에 개설한 계좌입니다. 증권계좌는 사업용계좌로 신고할 수 없습니다.
미사용 시 가산세(미사용금액의 0.2%)가 붙습니다.

### ③ 사업 매출과 투자 자금이 섞입니다
매출을 증권계좌로 직접 받으면 부가세·소득세 신고 근거가 흐려지고,
해외에서 외화를 지속적으로 수취하는 경우 외국환거래법상 증빙 문제도 생깁니다.

### ✅ 대신 이렇게 하면 됩니다

```
해외 결제 (USD)
  → 사업자 명의 외화 은행계좌 (또는 Wise/Payoneer 비즈니스 계정)
  → 매출로 장부 처리 · 세금 신고
  → 세후 자금을 대표자 개인 자금으로 인출
  → 그 다음에 본인 판단으로 증권계좌 이체
```

**결제 → 사업자 은행계좌**까지가 시스템이 관여하는 범위이고,
그 이후 자금 운용은 별개의 개인 결정입니다.
"달러로 받는다"는 목표 자체는 **사업자 외화계좌**로 달성할 수 있습니다.

> 저는 투자 관련 조언을 드릴 수 없습니다. 자금 운용 방식은 세무사·재무 전문가와 상의하세요.
> 여기서 정리한 건 **결제 대금이 도착해야 하는 계좌의 요건**까지입니다.

**확인할 것**
- [ ] 거래 은행에 **사업자 외화계좌(USD)** 개설 가능 여부 문의
- [ ] 세무사에게 사업용계좌 신고 및 외화 매출 처리 방법 확인
- [ ] PG사에 외화 정산 지원 여부와 정산계좌 요건 확인

## 2. 상품이 두 단계라 결제 구조도 둘로 나뉩니다

실물과 디지털은 **쓸 수 있는 결제사 자체가 다릅니다.**

| | 1단계: 실물 인쇄본 | 2단계: 앱 프로그램 (디지털) |
|---|---|---|
| 청약철회 | 수령 후 7일 원칙 | 제공 개시 시 제한 가능(조건부) |
| 배송 | 필요 (국내·국제) | 없음 |
| 해외 세금 | 수출, 수취인 관세 부담 | **각국 VAT/GST 등록 의무** |
| Paddle·Lemon Squeezy | ❌ **사용 불가** (디지털 전용) | ✅ 최적 |
| 재고 | 있음 | 없음 |

> ⚠️ **Paddle과 Lemon Squeezy는 디지털 상품 전용입니다.** 실물 책은 취급하지 않습니다.
> 1단계에서 이 서비스들을 쓸 수 없으니, 해외 결제 수단을 단계별로 따로 잡아야 합니다.

## 3. 결제사 조합 (권장안)

### 1단계 — 실물 인쇄본
| 시장 | 권장 | 비고 |
|---|---|---|
| 국내 | **토스페이먼츠** 또는 **포트원** | 카드+간편결제. 원화 정산 |
| 해외 | **Stripe** | 실물 가능. 세금은 직접 처리 |

### 2단계 — 앱 프로그램 (디지털)
| 시장 | 권장 | 비고 |
|---|---|---|
| 국내 | 1단계와 동일 | |
| 해외 | **Paddle** (Merchant of Record) | 각국 VAT/GST를 Paddle이 대신 처리 · USD 정산 |

### ⚠️ 2단계에서 반드시 검토할 것 — 앱스토어 인앱결제
앱 안에서 디지털 콘텐츠를 팔면 Apple·Google이 **인앱결제를 요구**하며 수수료가 15~30%입니다.
웹에서 결제하고 앱은 로그인해서 이용만 하는 구조로 설계하면 우회 여지가 있지만,
스토어 심사 정책이 자주 바뀝니다. **앱 기획 단계에서 결제 위치를 먼저 정하세요.**

## 4. 실물 판매 실무 (1단계)

### 청약철회·환불
| 상황 | 처리 | 반품비 |
|---|---|---|
| 배송 전 취소 | 전액 환불 | 없음 |
| 수령 후 7일 내 단순 변심 | 환불 | 소비자 부담 |
| 파본·오배송·하자 | 환불 또는 교환 | 사업자 부담 |
| 사용·훼손으로 재판매 불가 | 제한 가능 | — |

> 내용 확인을 위한 **개봉은 훼손이 아닙니다.** "개봉 시 환불 불가"는 무효입니다.
> 환급 기한은 반환받은 날부터 **3영업일**입니다.

### 해외 배송 — 경제성을 먼저 따져보세요
₩16,900짜리 책 한 권을 해외로 보내면 **배송비가 상품가에 육박하거나 넘습니다.**
반품이 발생하면 국제 반송비까지 더해집니다.

**대안 두 가지**
1. 해외는 1단계에서 **예약만 받고**, 2단계(앱 프로그램)부터 실판매 개시
2. 해외는 **묶음 판매**나 배송비 별도 청구로 최소 단가를 맞춤

> 어느 쪽이든 구매 페이지에 **배송 가능 국가·배송비·예상 소요일·관세는 수취인 부담**을
> 명시해야 합니다 (전자상거래법 제13조).

### 필요한 것
- [ ] 반품 수령 주소 (사업장 주소와 동일해도 됨)
- [ ] 배송사 선정 (국내 / 국제)
- [ ] 재고 수량 관리 방법
- [ ] 배송 상태 안내 메일 템플릿

## 5. 회원제 설계

앱 프로그램을 회원 전용으로 하기로 했으므로, 회원 체계가 필요합니다.

### 약관·문서
- [ ] 이용약관에 **회원 조항 추가** — 가입·자격·이용제한·탈퇴
- [ ] 회원가입 화면의 필수/선택 동의 분리
- [ ] 탈퇴 절차 안내

### ⚠️ 연령 기준이 두 개입니다 — 헷갈리기 쉬움

| 기준 | 근거 | 무엇에 적용 |
|---|---|---|
| **만 14세** | 개인정보보호법 제22조의2 | **회원가입(개인정보 수집)** 에 법정대리인 동의 필요 |
| **만 19세** | 민법 제5조 | **결제(계약)** 에 법정대리인 동의 필요 |

타깃이 10대라 **둘 다 실제로 발생합니다.** 중학생은 14세 미만일 수 있습니다.
가입 화면에는 14세 기준, 결제 화면에는 19세 기준이 각각 필요합니다.

> 현재 [privacy.html](../privacy.html) 제9조에 "만 14세 미만 개인정보를 수집하지 않는다"고
> 써두었는데, 회원제를 도입하면 **가입 시 실제 연령 확인 절차**를 붙여야 문구와 실제가 맞습니다.

### 탈퇴
```
탈퇴 요청 → 본인 확인 → 회원정보 삭제
  → 단, 거래기록은 법정 기간 분리 보관 (삭제 불가 — 7장)
```
탈퇴 화면에 "거래기록은 관계 법령에 따라 보관된다"고 미리 고지해야 분쟁이 없습니다.

### 휴면계정
개인정보 유효기간제(1년 미접속 시 파기·분리보관)는 **2023년 개정으로 폐지**되어
이제 법적 의무가 아닙니다. 운영 정책으로 자율 결정하면 됩니다.

## 6. 미성년자 처리 (확정)

### 결제 직전 화면
```
□ 만 19세 미만인 경우 법정대리인의 동의를 받았음을 확인합니다.  [필수]
```
- 체크 없이는 결제 진행 불가
- 확인 시각을 주문 기록에 함께 저장 → 분쟁 시 근거
- 법정대리인이 취소를 요구하면 **원칙적으로 환불에 응해야 합니다**
  (체크박스는 분쟁 방어 근거이지 취소권 배제 수단이 아닙니다)

### 회원가입 화면 (2단계)
```
생년월일 입력 → 만 14세 미만이면 법정대리인 동의 절차로 분기
```

> 혼자 처리하려면 국가별 등록이 필요해 현실적으로 부담이 큽니다.

## 8. 개인정보처리방침 개정 항목

판매·회원제 도입 시 [privacy.html](../privacy.html)에 반영해야 합니다.

- **수집 항목 추가**: 성명, 배송지, 연락처, 생년월일(연령 확인), 주문·결제 내역

- **만 14세 미만 처리 절차** 구체화 — 현재 문구는 "수집하지 않음"
